Introduction
FlutterFlow's drag-and-drop builder, action flow editor, and built-in widgets cover a huge
percentage of app-building needs. But every developer eventually hits a wall: a complex
calculation, a third-party SDK that has no native FlutterFlow integration, a performance-critical
loop, or a piece of business logic that's just too messy to express with visual action blocks.
This is where Custom Dart Actions come in. They let you drop straight into raw Dart code, write
exactly the logic you need, and plug the result right back into your visual app — getting the best
of both worlds: speed of visual development plus the full power of Dart/Flutter.

1. What Are Custom Dart Actions?
A Custom Action in FlutterFlow is a standalone Dart function that you write yourself. It lives
outside the visual Action Flow editor but can be called from anywhere inside it — buttons, page
load triggers, backend calls, widget states, you name it.
Use Custom Actions when you need to:
• Perform complex math/logic (distance calculations, sorting, filtering)
• Call a third-party API or SDK not natively supported
• Manipulate data structures (JSON parsing, list transformations)
• Run platform-specific code
• Improve performance by avoiding multiple chained visual actions
Tip: If you find yourself chaining 8–10 visual actions just to transform some data, that's usually a
sign a Custom Action would be cleaner and faster.

double calculateDistance(

const double earthRadiusKm = 6371;
double dLat = _degreesToRadians(targetLat - userLat);
double dLng = _degreesToRadians(targetLng - userLng);
double a = sin(dLat / 2) * sin(dLat / 2) +
cos(_degreesToRadians(userLat)) *
cos(_degreesToRadians(targetLat)) *
sin(dLng / 2) *
sin(dLng / 2);
double c = 2 * atan2(sqrt(a), sqrt(1 - a));
return earthRadiusKm * c;
}
double _degreesToRadians(double degrees) {
return degrees * (pi / 180);
}

5. Common Errors & How to Fix Them
• The function 'X' isn't defined: Helper function name doesn't match what's called —
Fix: Make sure helper function names match exactly (case-sensitive)
• Type 'X' not found: Missing import for a custom Data Type or struct — Fix: Add the
correct import path from /backend/schema/...
• Undefined name 'pi' / 'sqrt': Missing dart:math import — Fix: Add import 'dart:math'; at
the top
• Package not recognized: Dependency not added or not saved — Fix: Re-check App
Dependencies, re-save, and re-open the editor
• Returns null unexpectedly: Return type mismatch — Fix: Ensure your function's return
statement matches the selected Return Type exactly
• Action doesn't appear in Action Flow list: Forgot to save — Fix: Click Save in the
Custom Action editor first
6. Best Practices for Writing Custom Actions
29. Keep actions small and single-purpose. One action = one job. Easier to test, debug, and
reuse.
30. Use descriptive names for both the action and its arguments — your future self (and
teammates) will thank you.
31. Always test before connecting to the UI — catch errors early in the isolated test panel.
32. Avoid heavy loops on the main thread for large datasets — consider using Future and
async/await for anything that takes time (API calls, large filtering operations).
33. Comment your code, especially helper functions — this matters a lot when other
developers (or future you) need to maintain it.
34. Reuse helper functions across actions by keeping consistent naming and structure —
you can copy-paste shared helpers like _calculateDistance between actions.
